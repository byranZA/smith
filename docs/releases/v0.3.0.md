# smith v0.3.0

v0.2.0 put the loop on a box. v0.3.0 has the loop check its own work: a repo can turn on a review that reads the whole work branch once the last task closes, files what it finds as new tasks and works them in the same run. A repo's gitignored files, such as `.env`, now reach every worktree the loop works in, on a box and on your own machine, and a coding agent that drives smith can read how from the binary itself.

## Upgrading

- **Upgrade each box:** `smith update` offers to upgrade every box, or run `smith machine upgrade <box>` for each. On-box smith refuses a version mismatch, and the config stage now runs on the box's smith. → [Version skew](../on-box.md#version-skew)
- **Gitignore every repo placement before the next loop run.** The loop now places a repo's blueprint placements into its task worktrees, and refuses to start when a placement's destination is not gitignored in the repo, naming each path. A repo whose blueprint declares a placement at a tracked or unignored path, which v0.2.0's loop ignored, now stops: add the path to the repo's `.gitignore`. → [Task worktree placements](../loop.md#task-worktree-placements)
- **Off a box, keep each placed file in your checkout.** A local `loop run` in a repo that a blueprint in your config home declares copies each placement's path from your checkout, and stops before any task is touched when one is missing, tracked or not ignored there. A repo no blueprint declares runs as before. → [Task worktree placements](../loop.md#task-worktree-placements)
- **Drop the `prepare:` copy workaround.** A `prepare:` such as `cp ../../.env .env` is no longer needed, and since v0.2.0 put local task worktrees in the state home, no relative path reaches your checkout anyway.
- **Optionally, add the repo guide:** run `smith repo init` again in a repo that has a repo file. It leaves `.smith/repo.yaml` alone, writes `.smith/README.md`, and offers to point `AGENTS.md` or `CLAUDE.md` at it. → [The repo file](../loop.md#the-repo-file)

## What's new

- **The review:** set `roles.review` in the repo file and an unattended run reviews the whole work branch once every task is closed, against the spec, the repo's standards and its maintainability. The loop posts the review on the issue, files each finding as a sub-issue for an agent or a human, labels the issue `smith:reviewed` and works the agent tasks it filed, without reviewing again. `--no-review` skips it for one run, and a filing that `gh` interrupts is finished by the next run from the review comment. → [The review](../loop.md#the-review)
- **Your own review prompt:** `smith loop prompt review > .smith/review.md` ejects the built-in review prompt, so the review can call your own review skill. A review on pi needs one. → [The review prompt](../loop.md#the-review-prompt)
- **A repo's files in every task worktree:** the loop places the repo's blueprint placements into each task worktree before preparing it, so `prepare:` and the agent both see a `.env`. On a box the bytes are the ones setup staged; off a box they are copied from the checkout you run the loop in, found by matching its `origin` to the blueprints in your config home. → [Task worktree placements](../loop.md#task-worktree-placements)
- **A quieter loop:** the loop prints one `smith: preparing the worktree of #N` line in place of the toolchain install and `prepare:` output, and prints the last 64 KiB of that output only when preparation fails. A human `session start` still streams it. → [`smith loop run`](../loop.md#smith-loop-run)
- **A guide for the agent that drives smith:** `smith help agents` prints the mental model, a verb map, the exit codes, the issue shape the loop expects and recipes, built into the binary so it matches the smith you run. `smith repo init` also writes `.smith/README.md`, a short note telling any agent in the repo that smith drives it. → [The repo file](../loop.md#the-repo-file)
- **Where a spec's work will land:** `smith loop list` prints the work branch and base branch a run would use, and takes `--branch` and `--base`, so an agent can commit a spec's design docs to its work branch before the run. → [`smith loop list`](../loop.md#smith-loop-list)
- **Workspace failures that say what they cost:** when a box placement or the box toolchain fails, the workspace stage skips the repos that need it, reported as `skipped` with the failure at the root, instead of cloning them into misleading authentication errors. Sibling repos still converge, and the orphans scan always runs. → [Prerequisites and skips](../workspace.md#prerequisites-and-skips)

## Fixes

- The config stage applies the staged tree on the box in one call: it checks every entry before writing any, stops at the first write that fails, naming it, and prunes only once every write has landed. A failed probe no longer reads as a missing file, and a failure partway no longer leaves a half-staged box with a prune computed from an empty listing. → [Config staging](../on-box.md#config-staging)
